# edtable

## Как запустить у себя

1. Забрать код

2. Создать виртуальное окружение

```bash
python -m venv .venv
```

3. Активировать его

```bash
.venv\Scripts\Activate.ps1
```

или: `source .venv/bin/activate`.

4. Поставить зависимости

```bash
pip install -r requirements-dev.txt
```

(`requirements.txt` — то, что нужно приложению, `requirements-dev.txt` — плюс инструменты разработки.)

5. Прогнать тесты

```bash
pytest
```

6. Прогнать ядро в консоли на тестовой школе

```bash
pip install -e .
python -m edtable examples/school.json
```

В `examples/school.json` расписание удаётся устроить всем, и аукцион ничего
не решает. Чтобы увидеть, как ставки конкурируют, а биржа выкупает проигранное,
есть `examples/tight.json`.

Полезные флаги:

- `--parser lmstudio` — разбирать пожелания локальной моделью через LM Studio
  (вкладка Developer → Start Server, загрузить любую текстовую модель).
  `--model <id>` — какую именно, по умолчанию берётся уже загруженная.
  Если сервер не отвечает, разбор откатывается на правила.
- `--repl` — после расчёта открыть интерактивную биржу: `g 5a` — сетка класса,
  `t ivanova` — сетка учителя, `p` — очки, `m popov вт3 ср2` — заявка на перенос.
- `--ask` — спрашивать согласие второй стороны обмена вручную.
- `--teachers` — печатать и сетки учителей, `--time-limit 30` — секунд на солвер.

## Как устроен алгоритм

Подробное описание — в [docs/algorithm.md](docs/algorithm.md).

```
пожелания текстом ──> разбор (правила или LM Studio) ──> отсев невыполнимого
   ──> аукцион: у всех по 100 очков ──> CP-SAT: ставки = веса цели
   ──> базовое расписание (оптимум с доказательством)
   ──> биржа обменов: каждая сделка проверяется солвером ──> итоговое
```

- **Жёсткие правила** задаёт администратор: накладки, вместимость и оснащение
  кабинетов, свой кабинет у класса, недоступность, закреплённые уроки, лимиты
  в день (в том числе по предметам), сдвоенные уроки. Их нарушать нельзя.
- **Мягкие правила** — штрафы в тех же очках, что и ставки: окна у классов и
  учителей, трудные предметы на 6-7 уроке, один предмет дважды в день вразбивку.
- **Аукцион**. Каждый участник (учитель или класс) раскладывает 100 очков по своим
  пожеланиям. Ставка выигрывается целиком или никак. Невыполнимые пожелания
  отсеиваются заранее, чтобы очки не сгорали зря.
- **Солвер** максимизирует сумму выигранных очков плюс `fairness` × очки самого
  обделённого минус штрафы администратора (окна у классов). Если статус OPTIMAL,
  лучшего расписания при этих ставках не существует.
- **Биржа**. Перенос, обмен местами, обмен со сдвигом или минимальная перестановка
  в классе. Обмен не может отнять очки ни у кого, кроме инициатора, и не может
  добавить окон; у тех, чьи уроки сдвинулись, спрашивают согласие.

## Структура

```
src/edtable/
  scheduler/           ядро: алгоритм составления расписания, не зависит от UI
    models.py          сущности: преподаватель, группа, аудитория, предмет, слот, занятие
    problem.py         входные данные для алгоритма (SchedulingProblem)
    schedule.py        результат (Schedule)
    constraints/       правила: hard.py — жёсткие, soft.py — мягкие (штрафы)
    wishes.py          пожелания участников и ставки на них
    auction.py         бюджет очков, отсев невыполнимого, итоги аукциона
    solvers/           алгоритмы; base.py — интерфейс Solver, cpsat.py — CP-SAT
    exchange.py        биржа обменов поверх готового расписания
    validation.py      проверка готового расписания по ограничениям
    exceptions.py      ошибки библиотеки
  llm/                 разбор пожеланий: rules.py — регулярки, lmstudio.py — локальная модель
  scenario.py          загрузка тестового сценария из JSON
  cli.py               консольный прогон всего конвейера (python -m edtable)
examples/school.json   тестовая школа: 4 класса, 11 учителей, правила, пожелания, заявки
examples/tight.json    плотная школа (29 уроков из 30 слотов): ставки реально конкурируют
examples/realistic.json  5-7 классы по учебному плану: свои кабинеты, сдвоенная технология,
                       физкультура не чаще раза в день, СанПиН-штрафы, 13 учителей, 170 уроков
tests/                 тесты (pytest), повторяют структуру src/
pyproject.toml         описание пакета и настройки pytest, black, ruff
```
